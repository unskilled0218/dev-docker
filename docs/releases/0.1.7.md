## Changes

- Display live plain Docker build logs and safe workflow phase messages on stderr for local builds and publication, including step errors, staging reuse, and completed verification.
- Filter known credentials, supported Docker auth/password/token forms, configured proxy values, private paths, recognizable authorization/credential records, and URLs before display. Keep authenticated responses and other command output private.
- Bound log records, pending delivery, and stalled-output waiting through a supervised writer, preserving command limits, process cleanup, helper stdout, and release guards. Include the logging module in release identity.
- Add offline coverage for redaction across chunk boundaries, decoded Docker passwords, live delivery, backpressure, process cleanup, and build/publication outcomes.

## Verification limits

Build logs remain potentially sensitive: unknown credentials, custom encodings, and arbitrary downloaded-script output are not universally detectable. Offline tests use synthetic processes and fake service boundaries, not native builds or real publication. No TLS bypass, host trust change, or remote release repair is authorized.
