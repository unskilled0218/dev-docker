## Fixes

- Support first-time `base` and `npm` publication when Gitea returns HTTP 404 for missing named packages. Require verified individual-owner/repository authority and a complete successful filtered owner inventory before classifying their non-internal versions as absent.
- Preserve strict ordinary API reads, exact association checks after staging, required links, read-only completed retries, inventory limits, and no-reassignment/no-rollback safeguards. No prior local build or manual package creation is needed.
- Correct offline fixtures for the different missing-package behavior in Gitea `1.24.7` and `28.2.0`; cover first publication, contradictory or inaccessible evidence, pagination limits, and private diagnostics.

## Verification limits

Offline tests use fake external boundaries and do not establish real image builds, registry publication, or live package visibility. No authenticated production probes or publication are performed by this change. Internal-only or versionless package records can still cause safe link refusals; this fix does not authorize reassignment, cleanup, or repair of ambiguous releases.
