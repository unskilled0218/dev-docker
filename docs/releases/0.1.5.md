## Changes

- Copy `ntfy.lanCA.crt` alongside `git.lanCA.crt` into the base image before updating certificate trust. Both automated build modes now capture and supply both files.
- Require an existing ntfy CA file through `ntfy_certificate_file`, defaulting to `/usr/local/share/ca-certificates/ntfy.lanCA.crt`, or `BUILD_NTFY_CERT_FILE`. Keep Git's existing setting and override unchanged.
- Bind both certificate filenames and contents in the release fingerprint, recheck both inputs before publication writes, and preserve captured bytes in build contexts. Old release identities remain conflicts rather than repair targets.
- Add offline regression coverage for certificate selection, invalid inputs, sanitized errors, fingerprints, change guards, snapshot isolation, context contents, and Dockerfile trust ordering.

## Verification limits

Offline tests use fake external commands and do not prove valid CA contents, native image builds, live ntfy connectivity, or registry publication. Host trust remains unchanged, and no TLS bypass is introduced. Supply both valid certificates separately before a real build.
